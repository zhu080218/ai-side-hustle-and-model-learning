## 1. 一张地图

```
原始语料 → 预训练（自监督，学"世界如何运作"）
        → SFT 微调（学"按指令做事"）
        → 偏好对齐（学"做得更好/更符合人"）
        → 推理时：RAG（接外部知识）+ 工具调用（接外部动作）+ 提示工程（接即时约束）
        → 评测贯穿全流程（否则不知道有没有变好）
```

关键认知：**预训练学能力，微调学格式与风格，RAG 学事实，对齐学偏好，评测学判断**。绝大多数人想解决的问题，落在后三者，而不是第一个。

## 2. 自监督学习：标签从哪来

### 核心思想

监督学习需要人标注 \((x, y)\)。自监督从数据本身构造监督信号：把输入的一部分当问题、另一部分当答案。因此**语料本身就是标签**，这是大模型能吃下整个互联网的根本原因。

### 四类目标函数

| 类型 | 构造方式 | 代表 | 擅长 |
|---|---|---|---|
| 自回归语言建模 | 用前 t 个 token 预测第 t+1 个 | GPT 系 | 生成、通用能力 |
| 掩码重建（MLM） | 遮住 15% token 让模型填 | BERT | 理解、分类、检索 |
| 对比学习 | 同一样本的两个视角拉近，不同样本推远（InfoNCE） | CLIP、SimCSE、句向量模型 | 跨模态对齐、embedding |
| 去噪自编码 | 加噪再还原 | Diffusion、MAE | 图像生成、表征 |

目标函数统一写法：最小化 \(-\log p_\theta(y \mid x)\)，\(x\) 是给定部分，\(y\) 是要预测部分。换的只是「怎么切分」。

### 为什么这样能学到「理解」

- **压缩即理解**：要准确预测下一个 token，必须隐式建模语法、事实、因果、语用。预测误差 = 压缩成本，压低它等于桎取数据里的规律。
- **梯度的信噪比**：海量 token 让梯度方向稳定，模型才能在被参数化的巨大空间里找到可泛化的解。
- **涌现**：规模跨过阈值后，少样本学习、推理链等能力突然出现，这不是设计出来的，是规模与数据多样性的副产品。

### 决定成败的不是架构，是数据

- 配比：代码、数学、多语言、对话、长文的混比直接决定能力偏科。
- 去重：重复样本会让模型「背」而不是「学」，还会放大有害内容。
- 质量过滤：分类器打分 + 规则过滤，比堆量有效。
- 课程：先通用后领域、先短后长，或按难度退火。

### Scaling Law 的实用含义

损失随参数量、数据量、算力按幂律下降，但收益递减。实践含义：**同等预算下，数据质量与训练 token 数的边际收益常高于盲目加参数**；小模型 + 高质量数据 + 长训练，能在特定领域打败大模型通用版。

## 3. 三种「让模型学我的东西」的方式

| 手段 | 改什么 | 成本 | 适合 | 不适合 |
|---|---|---|---|---|
| 提示工程 | 不改权重，只改上下文 | 分钟级、几乎零成本 | 风格、格式、少量规则 | 大量私有知识、稳定行为 |
| RAG | 外挂检索库 | 天级、几百到几千元 | 事实型问答、文档多且常更新、需引用出处 | 改变说话方式、复杂推理链 |
| 微调 | 改权重 | 天到周级、几百到几万元 | 固定格式输出、领域术语、语气、任务专用小模型 | 频繁变动的知识、事实记忆 |

**决策顺序**：先提示 → 再 RAG → 最后微调。80% 的需求在前两步就解决了；一上来就微调，通常是把「知识问题」当成了「能力问题」。

判断口诀：**答案在文档里 → RAG；答案是「怎么说」→ 微调；答案在流程里 → Agent。**

## 4. 微调：SFT、LoRA/QLoRA、数据与超参

### 4.1 SFT 在做什么

在「输入 → 期望输出」的成对数据上继续做下一个 token 预测，让模型把分布重心移到你的任务上。它教的是**行为与格式**，不是新增知识。想让模型「记住」事实，SFT 需要重复很多遍且容易幻觉，不如 RAG。

### 4.2 全参 vs 参数高效（PEFT）

| 方式 | 显存（7B 量级） | 效果 | 场景 |
|---|---|---|---|
| 全参微调 | 4×80G 或 8×40G 起 | 上限最高 | 有充足数据与算力，做领域基座 |
| LoRA | 单卡 24G 可跑 | 接近全参（数据够时） | 绝大多数个人与小团队 |
| QLoRA（4bit 基座 + LoRA） | 单卡 12–16G，7B 可压到 8–10G | 略降，仍可用 | 消费级显卡、单机实验 |

LoRA 原理：冻结原权重 \(W\)，只学一个低秩增量 \(\Delta W = BA\)，其中 \(B \in \mathbb{R}^{d \times r}\)、\(A \in \mathbb{R}^{r \times k}\)，秩 \(r \ll d\)。可训练参数降到 0.1%–1%，且可插拔、可多任务并存。

### 4.3 常用超参起点（LoRA）

- 秩 `r`：8–64（任务越像「新技能」取值越大；改风格 8–16 够）
- `lora_alpha`：通常取 2r
- 学习率：LoRA 1e-4 ~ 2e-4；全参 1e-5 ~ 5e-5
- 目标模块：注意力 q/k/v/o + MLP 全上，效果优于只上 q/v
- batch：显存不够就梯度累积；`gradient_checkpointing=True` 省 30%–40% 显存、慢 20% 左右
- epochs：1–3，超过往往过拟合；用验证集 loss 早停
- 精度：bf16 优先；4bit 量化训练用 QLoRA

### 4.4 数据是 90% 的工作

- **数量**：格式/风格类 200–2000 条可用；复杂任务 5000+；不够就先合成再人工筛。
- **质量**：一条错样本的伤害大于十条好样本的收益。抽样 50 条人工读，是必要工序。
- **多样性**：覆盖真实输入的分布（长短、口语/书面、边界情况、该拒答的情况），只在「理想问法」上训练会一上线就崩。
- **格式**：统一模板（system / user / assistant），训练与推理模板必须一致，否则效果腰斩。
- **防泄漏**：验证集与训练集去重，否则指标虚高。

### 4.5 灾难性遗忘与缓解

微调后通用能力下降是常态。缓解：混入 10%–30% 通用指令数据、降低学习率与秩、只训部分层、用 KL 正则约束偏离。上线前必须回归测试「原来会的还会不会」。

### 4.6 微调值不值

值：输出格式极其固定、要压成本（小模型替代大模型 API）、要私有部署、要低延迟。
不值：知识频繁更新、数据不足 200 条、只是想把话说得客气点。

## 5. RAG：为什么它比微调更常被选

### 5.1 全链路

```
文档 → 解析（PDF/表格/扫描件）→ 清洗 → 切片 → 向量化 → 建索引
问题 → 改写 → 检索（向量 + 关键词混合）→ 重排 → 上下文组装 → 生成 → 引用与拒答
```

### 5.2 每一步的失败长什么样

| 环节 | 常见失败 | 修法 |
|---|---|---|
| 解析 | PDF 双栏错序、表格丢失、扫描件无 OCR | 版面分析模型、表格单独转 Markdown、OCR 兜底 |
| 切片 | 切太碎丢上下文；切太大稀释相关性 | 300–800 token、10%–20% 重叠；按语义/标题切；小块检索+大块喂给模型 |
| 向量化 | 领域词、编号、缩写检索不到 | 换领域 embedding；查询改写（同义扩展、HyDE） |
| 检索 | 只走向量，漏掉精确匹配 | 混合检索（BM25 + 向量），RRF 融合 |
| 重排 | 相关文档排在第 8 位被截断 | 加 cross-encoder rerank，取 top 20 重排到 top 5 |
| 组装 | 上下文塞满噪声，模型被带偏 | 只放必要片段 + 明确指令「仅依据资料回答」 |
| 生成 | 无据作答、幻觉 | 强制引用编号、无据则拒答、答案与引用做一致性检查 |
| 更新 | 文档改了索引没更新 | 增量索引 + 文档版本号 + 定时重建 |

### 5.3 评测 RAG 的两个层面

- **检索层**：命中率 Hit@k、召回 Recall@k、MRR。用 50–100 条「问题 → 正确文档」的标注集。
- **生成层**：忠实度（答案是否被所给资料支持）、相关性、拒答正确率。可用 LLM 打分 + 人工抽检 20%。

**没有评测集的 RAG 项目，等于在猜。**

### 5.4 什么时候不该用 RAG

问题需要跨文档聚合统计、需要复杂多跳推理、语料本身是结构化数据库（那是 SQL/Agent 的活）。

## 6. 偏好对齐：RLHF、DPO、GRPO

- **RLHF**：SFT → 训奖励模型（人对成对回答打分）→ PPO 优化策略，同时用 KL 惩罚防止偏离。效果强，但流程重、不稳定。
- **DPO**：直接用「好回答 / 差回答」成对数据优化，跳过奖励模型与 RL，工程简单，个人可做。是当前低成本首选。
- **GRPO**：同一问题采样多条回答，用组内相对优势当基线，省掉价值网络，适合有可验证答案的任务（数学、代码）。
- 代价：对齐会带来「过度礼貌」「回避」等副作用，而且人类偏好本身有偏。数据里偏好什么，模型就变成什么。

## 7. 评测：没有评测就没有进步

- **自建 eval set**：50–200 条真实问题 + 期望要点，比任何公开榜单都重要。公开榜单存在污染与过拟合。
- **LLM-as-judge 的坑**：位置偏好、长度偏好、自我偏好。缓解：交换顺序双打分、给评分细则（rubric）、关键项人工复核。
- **必测四类**：能力（该会的会不会）、格式（能否稳定输出）、安全（该拒的拒没拒）、回归（原来会的忘没忘）。
- **指标选择**：事实任务看准确率与忠实度，生成任务看人评偏好，代码看通过率（执行验证优于相似度）。

## 8. 四阶段自学路线

> 时间按每周 10–12 小时估算。允许跳阶段，但必须过验收。

### 阶段 0：看懂（1–2 周）

- 目标：说清 token、embedding、注意力、logits、温度、上下文窗口分别是什么，以及一次前向传播发生了什么。
- 最小项目：手写一个 bigram 语言模型（几十行 numpy），在 tiny 语料上训练并采样。
- 验收：能用自己的话解释「为什么预测下一个词能学到语法」；能画出训练循环的五步。
- 资料取向：一篇图解 Transformer + 一份可跑的最小 GPT 实现（nanoGPT 类）。

### 阶段 1：会调用与改造（3–6 周）

- 目标：跑通「API 调用 → 结构化输出 → RAG → LoRA 微调」全链。
- 最小项目（三件套）：
  1. 一个带引用与拒答的 RAG 问答（50 份文档，20 条测试问题，命中率 ≥ 80%）。
  2. 一个 LoRA 微调（500 条自有数据，格式遵从率 ≥ 90%）。
  3. 一个评测脚本（能对比两次改动的得分）。
- 验收：能解释每个超参改动的后果；能定位一次答错的归因（检索错？切片错？提示错？）。
- 硬件：单卡 12–16G 或租云 GPU（按小时）。

### 阶段 2：会训练与评测（6–10 周）

- 目标：从零训练一个可用的中小模型，并建立可信评测。
- 最小项目：在 1–3B 规模上做 continued pretraining（领域语料），再 SFT，再用 DPO 或 GRPO 做一次对齐；全程有 loss 曲线与 eval 曲线。
- 验收：能解释 loss 突增/不降的 3 种原因；能证明「你的改动真的变好了」（不是靠感觉）；能算清这次训练花了多少钱。
- 关键技能：数据配比、分布式基础（DeepSpeed/FSDP 至少会配）、混合精度、检查点与恢复。

### 阶段 3：会选型与工程化（持续）

- 目标：把模型变成可运维的产品部件。
- 项目：量化部署（AWQ/GPTQ/llama.cpp）、并发与显存核算、缓存、灰度与回滚、监控（延迟、拒答率、幻觉率）。
- 验收：给出「这个场景该用 API 还是自部署」的成本对比表，误差在 20% 以内。

### 项目阶梯与验收表

| 阶段 | 项目 | 产出 | 验收指标 |
|---|---|---|---|
| 0 | bigram LM | 可训练可采样脚本 | 能解释每一步 |
| 1 | RAG 问答 | 服务 + 20 条测试集 | 命中率 ≥ 80%，拒答正确 |
| 1 | LoRA 微调 | 适配器 + 对比报告 | 格式遵从 ≥ 90%，通用能力不降超 5% |
| 2 | 领域继续预训练 | 检查点 + loss/eval 曲线 | 领域困惑度下降 ≥ 15% |
| 2 | 对齐实验 | DPO/GRPO 前后对比 | 偏好胜率 ≥ 60%，安全不退化 |
| 3 | 量化部署 | 压测报告 | 延迟与成本达标，精度损失 ≤ 3% |

## 9. 硬件与成本

| 任务 | 最低显存 | 现实建议 |
|---|---|---|
| 7B 推理（fp16） | 16G | 24G 更稳（含 KV cache） |
| 7B 推理（4bit） | 6–8G | 消费级卡可跑 |
| 7B QLoRA 微调 | 8–12G | 12–16G 舒适 |
| 7B LoRA（bf16 基座） | 20–24G | 4090 级别 |
| 7B 全参微调 | 70–80G | 多卡或 A100/H100 |
| 1–3B 从零预训练 | 单卡 24–40G（小批量） | 云上按小时更划算 |

云 GPU 粗略价：消费级卡 1.5–4 元/小时，A100 8–20 元/小时，H100 20–40 元/小时（随供需浮动）。一次 7B QLoRA 小实验通常 2–8 小时，成本可控制在几十到几百元。

时间估算经验：LoRA 训练速度约为全参的 2–4 倍；数据准备时间通常是训练时间的 5–10 倍。

## 10. 前置知识与学习陷阱

### 前置知识按需补，别先酰三个月数学

- 必会：矩阵乘法、softmax、交叉熵、链式法则、梯度下降。够读懂 90% 的论文公式。
- 用到再学：KL 散度（学对齐时）、InfoNCE（学对比学习时）、低秩分解（学 LoRA 时）。
- 编程：PyTorch 能写训练循环即可，不必先精通工程框架。

### 五个陷阱

1. **教程地狱**：收藏 50 个视频，跑通 0 个。止损：每看 1 小时必须跑 1 小时代码。
2. **追新不追原理**：模型周周更新，原理十年不变。止损：把 70% 时间放在数据、评测、检索这些不随版本变化的部分。
3. **只调参不看数据**：效果差 90% 是数据问题。止损：任何调参前先人工读 50 条样本。
4. **无评测的自我感觉**：改了十版，说不清哪版好。止损：先写 eval 再改模型。
5. **迷信微调**：把知识问题当能力问题。止损：先问「答案在文档里吗」。

### 一句话总结

**自监督让模型从数据里长出能力，微调让它服从你的格式，RAG 给它当下的知识，对齐让它符合人的偏好，评测让你知道自己在往哪走。** 学这五件事的顺序，比学哪个框架重要得多。
